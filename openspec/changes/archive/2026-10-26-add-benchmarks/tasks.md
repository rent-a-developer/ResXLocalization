## Manual steps and checks

Done by a maintainer on GitHub, outside this change's tasks: they need the pull request, its CI run or `main`.

- Create the `accept-allocation-increase` label in the repository, with a description saying it accepts a reviewed allocation increase for one pull request.
- On this pull request's run: `benchmark-changes` outputs `run=true`; the benchmark jobs and the report job pass within 10 minutes of the benchmark jobs starting; the report job shows the "No benchmark baseline" notice; the results are attached to the run. Locally, the job's `git diff` command against a documentation-only commit gives `run=false`.
- Add a post-merge checklist to the pull request's description: the first push to `main` creates the `benchmark-data` branch, the deployed site serves `benchmarks/latest/` and `benchmarks/history/`, and the next pull request's summary compares against that entry with both series.
