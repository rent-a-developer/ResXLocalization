# ResXLocalization

**Type-safe `.resx` localization for Avalonia and WPF - switch language _live_, no reload, no restart.**

Localizing a XAML app with plain `.resx` usually means string-typed keys that break silently at
runtime, and a language change that only takes effect after a restart. ResXLocalization fixes both:
you keep the `.resx` files and editors you already use, and get **compile-checked keys** and
**instant, in-place language switching**.

## Highlights

- ⚡ **Live, no-reload language switching** - set one property and every bound string updates in place.
- 🔒 **Type-safe, compile-checked keys** - a source generator turns every neutral `.resx` into strongly-typed keys, with or without a `.Designer.cs`, so a renamed or deleted resource becomes a **compile error**, not a runtime surprise.
- 📦 **Zero configuration** - install the package and build; the source generator and MSBuild wiring are included.
- 🗂️ **First-class multiple `.resx` support** - look up by typed key, scope to one file, or search across all registered files.
- 🔤 **Enum localization built in** - localize enum members by naming convention.
- 🧮 **Format arguments on the binding** - in XAML, give `{l:Localize}` and `{l:LocalizeEnum}` `<l:Argument>` children with constant or bound values, so enum labels take arguments too; in code, pass `MessageArguments.FromValues(…)` to `Localizer.Current.Get`.
- 🔢 **ICU MessageFormat, opt-in** - `plural` and `select` messages such as `1 file` / `5 files`, in code and in XAML, with the separate package `ResXLocalization.MessageFormat`.
- 🩺 **Lookup-failure diagnostics** - a visible, configurable `!key!` failure text plus a `LookupFailed` event, for a missing translation and for a value that cannot be formatted.
- 🌐 **Language-picker ready** - `GetAvailableCultures()` discovers the cultures your app actually ships.
- 🚀 **Native AOT & trim clean** (Avalonia package) - no reflection over your resources.

## Install

```shell
dotnet add package ResXLocalization.Avalonia   # Avalonia
dotnet add package ResXLocalization.WPF        # WPF
```

| Package | UI framework | Targets | Native AOT |
| ------- | ------------ | ------- | ---------- |
| `ResXLocalization.Avalonia` | Avalonia 12 | `net8.0` · `net10.0` | ✅ |
| `ResXLocalization.WPF` | WPF | `net8.0-windows` · `net10.0-windows` | ❌ (WPF limitation) |

Both share the same UI-agnostic engine (`ILocalizer` / `Localizer.Current`, `ResourceKey`), the same
source generator and the same MSBuild wiring, all of which arrive with the package you install.
`ResXLocalization.Core` comes along as a dependency, and one copy of it satisfies both UI packages in
an application that uses them together.

For messages whose wording depends on the arguments - `plural` and `select`, such as `1 file` /
`5 files` - add the opt-in package `ResXLocalization.MessageFormat` and call
`Localizer.Current.UseMessageFormat()` to format every localized text as ICU MessageFormat.

## Requirements

- An app targeting **.NET 8** or later, built with the **.NET 8 SDK or later**.
- For **Avalonia**: **Avalonia 12**. For **WPF**: **Windows**.
- `.resx` files. A `.Designer.cs` accessor is not required: every neutral `.resx` gets typed keys,
  with or without one.

## In three steps

**1. Add a neutral `.resx` and a satellite file per culture** - `Resources/AppStrings.resx` and
`Resources/AppStrings.de.resx`, with the same key names.

**2. Build.** The source generator emits a typed key class per neutral `.resx`, named
`<FileName>Keys` - by default in the namespace of the folder the `.resx` sits in. Only string entries
become keys.

```csharp
// <auto-generated/> - for AppStrings.resx:
public static partial class AppStringsKeys
{
    // The resource manager of AppStrings.resx - the one instance every key of this class uses.
    public static ResourceManager ResourceManager { get; } = new("YourApp.Resources.AppStrings", typeof(AppStringsKeys).Assembly);

    public static readonly ResourceKey Greeting = new("Greeting", ResourceManager);
    public static readonly ResourceKey WindowTitle = new("WindowTitle", ResourceManager);
}
```

**3. Bind, and switch.**

```xml
<Window xmlns:l="clr-namespace:RentADeveloper.ResXLocalization.Avalonia;assembly=ResXLocalization.Avalonia"
        xmlns:res="clr-namespace:YourApp.Resources"
        Title="{l:Localize {x:Static res:AppStringsKeys.WindowTitle}}">

  <TextBlock Text="{l:Localize {x:Static res:AppStringsKeys.Greeting}}" />

</Window>
```

```csharp
Localizer.Current.CurrentCulture = new CultureInfo("de");
```

Every `{l:Localize}` binding re-resolves immediately. No reload, no flicker.

For **WPF**, map `xmlns:l` to the WPF assembly instead:

```text
xmlns:l="clr-namespace:RentADeveloper.ResXLocalization.WPF;assembly=ResXLocalization.WPF"
```

### When you have to register a resource manager

A **typed** key carries its own `ResourceManager`, and a **scoped** lookup is given one, so neither
needs any registration. Registration exists for the **search-all** lookups - `{l:Localize Greeting}`,
`{l:LocalizeEnum}`, and `Get("Greeting")` - which search the registered managers in registration
order. Register the generated `<FileName>Keys.ResourceManager`, the instance the typed keys use:

```csharp
Localizer.Current.RegisterResourceManager(AppStringsKeys.ResourceManager);
```
